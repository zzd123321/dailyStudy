# 学习路线：从前端经验出发，做出完整 AI 应用

你已经会做页面、管理前端状态、调用接口。接下来要补的是：接口背后的程序怎样工作、数据怎样保存、模型怎样接入，以及系统出错后怎样恢复。

这条路线参考你提供的渡一“AI 大全栈”目录，以“团队知识与任务助手”为主线。按你的最新选择，先把 Java、数据库和 Spring Boot 学扎实，做出有数据、有权限的业务后端，再接 Python 和 AI。两门语言分阶段承担不同任务，避免刚入门就同时维护两套后端。

## 先看最终要做出的东西

假设用户上传一份产品文档，然后提出三个要求：

1. “帮我提炼成五条要点。”——模型调用与结构化输出。
2. “退款规则是什么？告诉我依据在哪一段。”——文档检索、RAG 与引用。
3. “把待办事项加到我的工作空间。”——业务接口、权限与工具调用。

要把这些功能做可靠，页面只是其中一层：

```text
+---------------- 用户界面 ----------------+
| 上传文档、提问、展示流式回答、取消与重试 |
+-----------------------------------------+
                    ↓
+--------------- Java 业务服务 ------------+
| 用户、工作空间、权限、条目、任务、事务   |
+-----------------------------------------+
              ↓                 ↓
        PostgreSQL        Python AI 服务
                          模型调用、文档处理、检索
                                  ↓
                         模型 API / 嵌入模型
```

这是后期的架构。第一版先用你熟悉的前端和 Java 服务完成笔记、任务与权限；第二版接 Python 模型服务；第三版增加 RAG 和 Agent。每一版都能独立运行与演示。

## 为什么这样安排

- **Java 优先。** 从当前的小程序走到对象、集合、数据库和 Spring Boot，先建立完整后端思维。
- **Python 随后承担 AI 能力。** 有了接口与数据库基础，再学习它的语法和生态，能把精力放在语言差异与模型应用上。
- **前端不从零重学。** 继续用已有 React/Vue 经验，重点补身份联调、流式显示、取消、引用和任务状态。
- **先看原始机制，再引入框架。** 先写 SQL 再用数据访问框架，先看模型请求再用 LangChain，先检索再封装 RAG。
- **每阶段有可运行产出。** 不等学完所有技术才开始项目；模型接入后就加入固定样例评估。

## 阶段 0：把页面和服务端接起来

现有四课是起步基础，已经按“小例子 → 解释 → 验证”的方式重写：

- [01 · Java 工具链与程序执行](/lessons/java-toolchain)：从源码、编译和 JVM 走到包、命令行参数、JAR 与 Maven 构建。
- [02 · HTTP 请求、响应与诊断](/lessons/http)：从笔记接口理解契约、方法、编码、分页、缓存与 CORS，完成客户端练习。
- [03 · Java 输入、控制流与方法](/lessons/java-control-flow)：用运算、字符串、分支、数组和方法完成统计程序，练习异常与调试。
- [04 · 请求链路与服务端状态](/lessons/request-lifecycle)：追踪数据生命周期，做独立文件保存实验，初步分析分层、并发、幂等与日志。

下一课继续 Java 的类与对象，再接集合、异常与文件读写。DNS、TCP、TLS、Cookie、Session、CORS 和 CSRF 在 Web 接口、登录与联调时展开。

**进入下一阶段的标准：** 能修改一个小程序；用 curl 创建并读取条目；解释编译成功、HTTP 成功与数据保存之间的区别。

## 阶段 1：系统学会 Java 编程

### Java：从计算器走向业务对象

类型与方法 → 类、构造器、封装、继承与多态 → 抽象类与接口 → List/Map 与泛型 → lambda 与 Stream → 异常 → 文件读写 → 日期时间 → 单元测试。注解与反射放在理解框架时展开。

将任务表示为对象，实现添加、查询、完成与删除。解释对象保存什么数据、方法改变什么状态、找不到任务时怎么办；再把文件保存与核心规则拆开。

接着学习线程、生命周期、线程安全、锁、线程池与并发集合。通过“多个请求一起修改任务”和“限制外部请求并发”解释它们的用途，而不是只背 API。Maven 依赖、插件、多模块在工程逐渐变大时补齐。

**产出：** 有清晰对象职责、文件保存和核心测试的 Java 任务管理器。能独立增加一个字段、修改一条规则，并解释错误输入怎样处理。

参考：[二哥的 Java 进阶之路](https://github.com/itwanger/toBeBetterJavaer) 的语法、对象、集合与异常；[Java 学习文档](https://dev.java/learn/)。并发和 JVM 深入篇在相应案例后再展开。

## 阶段 2：PostgreSQL、SQL 与 Java 数据访问

先学 PostgreSQL 安装 → DDL 与表结构 → 主键、外键与关系 → DML 增删改查 → JOIN 与聚合 → 分页 → 事务 → 索引与执行计划。用用户、工作空间、笔记和任务建模，问清哪些字段不能为空、哪些记录不能重复、哪些操作必须一起成功。

先在数据库工具里写 SQL，再用 JDBC 从 Java 调用。把连接、参数化查询、结果读取和资源关闭逐一解释，最后用 Flyway 管理表结构迁移。事务隔离和索引从实际问题进入，不只背概念。

将阶段 1 的任务管理器从文件保存改成数据库保存，验证进程重启后数据仍在。不先引入 ORM，让你看清程序实际执行了什么 SQL。

**产出：** Java 能保存、查询和更新业务数据；理解约束、事务边界和基本索引作用；不会通过拼接用户输入构造 SQL。

参考：[PostgreSQL 官方教程](https://www.postgresql.org/docs/current/tutorial.html)、[SQLBolt](https://sqlbolt.com/)、[Java JDBC 指南](https://docs.oracle.com/javase/tutorial/jdbc/basics/index.html)。JDBC 教程部分示例较旧，本项目继续使用 Java 21。

## 阶段 3：用 Java 构建真正的业务后端

学习 Spring Boot 的请求路由、依赖注入、配置、输入与输出对象、校验、统一异常和数据库访问。先把一个知识条目接口写清楚，再扩展整套业务。

按功能接入：知识条目与任务 CRUD → 分页与查询 → 事务 → 接口测试 → 登录 → 工作空间与资源权限 → 部署第一个单体服务。先写清楚基本接口，再叠加身份与权限。

安全部分明确学习 RBAC 的用户、角色、权限与资源范围；OAuth2 的角色和授权码流程；PKCE；OIDC 与身份认证；令牌生命周期。OAuth2 是授权框架，不能简单等同于登录；SPA 等公开客户端也不能保存 client secret。

进一步认识 Spring 自动配置、AOP、异步处理、任务调度与 Actuator。数据访问先选 JDBC/MyBatis 一条路线；JPA、WebFlux、GraphQL 在基础业务可运行之后比较，不同时引入多套框架。

网络基础在这里补齐 DNS、TCP、TLS、连接与响应超时；联调时再区分 CORS、Cookie、Session、token 和 CSRF。Redis 先用于具体的缓存问题，不提前铺开整套中间件。

特别解决三件事：

- 身份从哪里来？前端提交的 userId 不能代替认证。
- 谁能读写哪条数据？知道 ID 不等于有权限。
- 一项业务涉及多个修改时，失败了怎样保持一致？

**产出：** 前端与 Java 服务组成可用的业务系统。用户能管理自己的资料与任务，错误输入和越权请求有明确处理。先完成并部署这个版本，后面再接 Python AI 服务。

首次部署从 Docker、Compose、Nginx 和环境配置入手，加入健康检查、基础日志与数据库备份；CI/CD 先做构建和测试，再接发布。阶段 8 会在 AI 系统加入后深化观测、容量、回滚和高可用。

参考：[Spring 入门指南](https://spring.io/guides)、[Spring Boot 参考文档](https://docs.spring.io/spring-boot/reference/)、[MyBatis](https://mybatis.org/mybatis-3/)。采用与 Java 21 兼容的稳定版本，并固定项目依赖。

## 阶段 4：Python 与 AI 服务的准备

此时你已经会写 Java 接口、SQL 和业务规则。Python 重点学习另一门语言的表达方式，以及它在模型调用、文档处理和数据工具上的生态；数据库和 HTTP 原理不从头重复。

### 先学会处理数据

按顺序学习：变量与类型 → 字符串 → 列表、元组、集合与字典 → 判断与循环 → 函数、作用域与 lambda → 类与对象 → 模块与包 → 异常 → 文件与 JSON → 类型标注 → 虚拟环境、依赖管理与断点调试。

你会反复处理一个例子：一组知识条目，包含 id、title、content。先在内存里筛选和统计，再从 JSON 文件读取。用你熟悉的 TypeScript 对照表达，重点解释两者的差异。

接着学习装饰器、迭代器与生成器、上下文管理器和常见标准库。事件循环、协程、Future 与 async/await 在接口请求和流式处理时学习；多线程、多进程在区分 I/O 等待与计算任务后再练习。

元类、描述符、对象创建细节与 ABC 保留为进阶专题。它们会用于解释框架设计，但不要求在第一次写接口之前全部掌握。monorepo、构建发布在出现多包和共享代码需求时学习。

### 再把函数变成接口

学习 FastAPI 路由、请求模型、响应模型、Pydantic 校验、HTTP 错误和 pytest。逐步引入包结构、业务逻辑、依赖注入、统一异常、中间件、文件上传、配置、日志和接口测试，再接入数据库。

接着学习 httpx、连接与读取超时，以及 async/await 在网络等待中的作用。特别区分数据库事务和等待模型的长耗时任务：不把整个模型等待过程无理由地包在数据库长事务中。

本阶段先返回固定摘要或本地计算结果，形成可测试的接口；模型接入后，页面结构不必推倒重来。

SQLAlchemy 与 Alembic 放在这个阶段：对照已经会写的 SQL，理解 ORM 和迁移，而不是让框架隐藏数据行为。Python 服务先返回固定摘要，让 Java 调用它，验证地址、契约、认证、超时和失败处理；下一阶段再替换成真实模型。

**产出：** Java 业务后端与 Python 小服务能够联调；知道哪些职责留在 Java，哪些放进 Python；能独立调试两端的数据交换。

参考：[Python-100-Days](https://github.com/jackfrued/Python-100-Days)、[Python 官方教程](https://docs.python.org/zh-cn/3/tutorial/)、[FastAPI](https://fastapi.tiangolo.com/zh/tutorial/)、[SQLAlchemy](https://docs.sqlalchemy.org/en/20/tutorial/)、[Alembic](https://alembic.sqlalchemy.org/en/latest/tutorial.html)。按主题选读，不照搬“100 天”的进度。

## 阶段 5：第一次完整 AI 应用

### 先理解模型输入输出

依次学习大模型与应用的区别、token、上下文窗口、消息角色、提示词、采样、模型选择、输入/输出计费。再用小例子解释神经元、前向传播、损失、梯度下降、词嵌入、注意力、Transformer、训练阶段和推理的区别；不把完整训练工程当成调用 API 的前置条件。

Jupyter 用于做小实验，NumPy 用于理解数组与向量，Pandas 用于清洗和统计评估数据，Matplotlib 用于观察结果。动画与 Seaborn 等扩展按需学习，不把整个数据分析工具库一次塞进基础课。

用一个供应商的官方 SDK 完成请求；把 API 密钥放在服务端，用测试替身在没有密钥时验证自己写的处理逻辑。固定接口和依赖版本，按实际模型支持范围选择功能。

### 做三个可以演示的功能

1. **摘要：** 输入文档，输出有限长度的要点。比较完整、空白、超长和含无关内容的输入。
2. **结构化提取：** 输出符合约定的字段，再由代码检查。模型说“这是 JSON”不等于数据满足规则。
3. **流式问答：** 前端逐步显示内容，支持取消、错误提示和重试。分清 HTTP 连接、事件流和模型 token。

随后学习会话历史、上下文裁剪、速率限制、超时与有限重试、输出长度与成本控制。提示词按“任务、输入、约束、输出格式、示例”组织，通过固定样例比较效果。

**产出：** 一个前后端打通的 AI 助手原型；能说明正常输出、失败处理、成本与限制。

参考：[Microsoft Generative AI for Beginners](https://github.com/microsoft/generative-ai-for-beginners) 的入门、提示词、文本生成、工具调用与 UX 部分；[Datawhale 动手学大模型应用开发](https://github.com/datawhalechina/llm-universe) 的模型介绍与 API 部分。资料里的供应商、SDK 和框架版本要与当前项目分别核对。

## 阶段 6：有依据、有引用的 RAG

先做“自己写检索与拼接”的小例子，再学习框架：读取文档 → 清洗 → 分块 → 嵌入 → 存储 → 检索 → 提供上下文 → 生成回答与引用。

先用 PostgreSQL + pgvector 减少组件数量，再按问题学习关键词检索、向量检索、混合检索、重排、分块优化与版本更新。

评估分成两部分：有没有找到正确资料？回答有没有受资料支持？加入找不到答案、资料冲突、过期内容和权限隔离的样例。

在此基础上再学习 LangChain 等工具的加载器、检索器、编排方式，比较与自己实现的对应关系。

对照渡一目录补充 LlamaIndex 的连接器、索引与 QueryEngine。先选一个框架做完项目，再比较另一个；GraphRAG、多模态 RAG、语义路由和缓存作为已有基线后的专题，不代替基础检索评估。

**产出：** 基于上传资料的问答，引用可追溯，无证据时有合理行为，不向无权用户返回文档。

参考：[Datawhale LLM Universe](https://github.com/datawhalechina/llm-universe) 的知识库、RAG 与评估部分；[pgvector](https://github.com/pgvector/pgvector)。

## 阶段 7：Agent、LangGraph、LangChain 与 MCP

先做只读工具，例如查任务、查文档；再实现需要确认的写操作。学习模型如何提出工具名称与参数，代码如何校验、执行并返回结果。

先用普通 Python 写“模型提出工具请求 → 执行工具 → 将结果交回模型”的循环，再认识 ReAct 和 Agent。工具调用、固定工作流和多步自主决策分别用一个小例子解释。

明确区别：固定步骤的工作流、模型动态选择工具的 Agent、用于连接工具与资源的 MCP。不要把三个名字当成同一种东西。

按顺序补参数规则、允许范围、权限、写操作确认、重复执行保护、超时、执行次数限制、审计、后台任务与恢复。模型输出或文档内容不能替代用户授权。

LangGraph 按状态、节点、边、消息与 Reducer → 工具节点 → 检查点与线程 → 子图 → 重试与容错 → 中断与人在回路 → 取消与事件流 → Store 与长期记忆推进。Agent Server 的部署 API 与服务配置在图的核心机制掌握后学习；开源能力、服务 API 和托管功能按所选版本分别核对。

再学习 LangChain 的结构化输出、中间件、动态提示词与模型，DeepAgent 的计划、文件工具、上下文压缩和子代理。涉及文件与代码执行时增加沙箱、资源隔离和权限；多 Agent、handoff 与 A2A 在单 Agent 已能验证后选学。

Prompt Engineering 是组织提示，Context Engineering 是组织模型看到的全部上下文；Harness、Loop、Graph 等名称用具体执行结构解释，不当成一组必须先背完的新术语。

**产出：** 助手能够查询并协助创建任务；执行范围可解释，失败可定位，中断后任务状态可恢复。

参考：[Microsoft AI Agents for Beginners](https://github.com/microsoft/ai-agents-for-beginners)、[MCP for Beginners](https://github.com/microsoft/mcp-for-beginners)。这两份作为后期选读入口，当前改版主要核对的是前面的入门教程。

## 阶段 8：观测评估、基础设施、部署与求职

### 先看清一次 Agent 执行

用 Langfuse 观察模型与工具调用链、耗时、token 与成本。学习提示词版本、数据集、人工与自动评估、离线实验、pytest 回归和线上告警。服务“没报错”与答案“符合预期”是两类检查。

### 再把多个组件稳定地运行起来

从 Docker Compose 起步，按实际问题增加模型网关的兼容性、路由、限流、熔断与回退；用对象存储保存文档和产物，用后台任务完成长流程。Nacos 动态配置、沙箱复用、AgentSpec 等基础设施专题在需要时展开，不先搭完整平台再做第一个应用。

Linux 基础 → Docker → 配置与密钥 → 数据库迁移 → 反向代理与 HTTPS → CI → 健康检查 → 日志与监控 → 备份与恢复。

Nginx 配合域名、DNS、TLS 与静态资源托管；云平台补安全组、IAM、对象存储与成本预算。后期用指标、日志与链路观察系统，再学习告警、压测、回滚和高可用。Kubernetes、Spring Cloud、Dubbo、消息队列与分库分表按目标岗位和规模需求拓展。

准备一组固定业务与 AI 问题，在修改前后比较功能、效果、响应时间与成本。补充测试、项目说明、架构图与完整演示；练习讲清楚“需求是什么、为什么这样设计、怎么验证、有哪些边界”。

**产出：** 能在干净环境部署，能定位一次真实失败，能独立修改关键逻辑的求职项目。

微调、本地模型部署和多模态可按目标岗位选学；预训练、分布式训练与深入算法研究需要另一套数学和训练路线。先完成 AI 应用岗位需要的交付能力。

### AI Coding 贯穿全程

用 AI 帮你解释报错、拆需求和检查代码，但练习要能自己复现。先写接口契约和验收条件，再生成实现；查看差异、运行测试、检查密钥与权限。后期学习 CLI、工具、MCP、Skill、Spec Coding、子代理与前后端自动化测试，不以“生成了很多代码”代替学会。

### 用一个主项目，而不是一次做完所有项目

主项目继续采用团队知识与任务助手，最后接入客服问答和工单流转，形成“知识治理 + 智能客服”的企业案例。AI 漫剧可选作多模态与 LangGraph 练习；内容审核平台和 FDE 项目作为后续拓展。Dify 用于比较低代码工作流与代码实现；微调在确有效果差距和数据条件后学习 LoRA/QLoRA、评估与部署。

## 资料怎么用，课程会怎么讲

本网站正文负责把概念教清楚，外部资料负责补例子与核对 API。每课采用：

1. 一个你能理解的具体问题。
2. 一个足够小的例子，明确输入与输出。
3. 按执行顺序解释代码，先解释中文含义再给术语。
4. 一次独立修改，预测并验证结果。
5. 可展开的进阶说明与参考答案。

基础文章选读 Javaer、Python-100-Days 与 MDN；AI 应用顺序参考 Microsoft 与 Datawhale 的公开目录。这里的讲解重新组织并使用仓库自己的例子，不复制原文或整套课程。
