# 从前端到 AI 应用全栈的学习路线

你已经有三年前端经验。接下来要理解并交付浏览器之外的部分：业务数据如何保存、服务端怎样校验权限、模型能力如何接到业务，以及失败后如何恢复。

Java 负责业务后端，Python 负责 AI 服务。先学会编写和解释程序，再接数据库与 Web 框架，最后引入大模型。路线按知识依赖组织，根据掌握程度推进。

::: tip 课程范围
目前已提供前 3 课的完整讲解、示例和练习。下方是后续知识路线，不是已经编写完成的全部课程；新内容会继续补充到同一网站。

## 第一层：程序与请求如何运行

理解 Java 源码、字节码与 JVM；HTTP 方法、URL、头和正文；输入解析、校验、控制流与方法。随后学习 DNS、TCP、TLS 的基本作用，接口契约，以及 Cookie、Session、CORS、CSRF 的关系。

**应能做到：** 独立运行并修改小程序，用 curl 重现接口请求，区分连接失败、HTTP 失败和业务输入错误。

- [01 · Java 工具链与程序执行](/lessons/java-toolchain)
- [02 · HTTP 请求、响应与诊断](/lessons/http)
- [03 · Java 输入、控制流与方法](/lessons/java-control-flow)

## 第二层：用 Java 组织真实业务

依次学习类与对象、构造器、封装、接口、集合、泛型、异常、文件读写、日期时间与单元测试。通过“命令行任务管理器”学习保存状态、查找任务、改变状态和处理不存在的 ID。

区分输入层、业务逻辑和存储层。集合组织内存数据，文件提供简单持久化，测试检查状态变化与失败分支。

**应能做到：** 独立添加、查询、完成和删除任务；解释职责划分；非法输入不破坏已有数据；测试覆盖核心规则。

参考：[Java 官方学习目录](https://dev.java/learn/)、[JUnit 用户指南](https://docs.junit.org/5.13.4/user-guide/)。

## 第三层：关系数据库与数据一致性

先学习表、主键、外键、约束，再写 SELECT、INSERT、UPDATE、DELETE、JOIN、聚合和分页。根据真实业务建模，再理解事务、隔离、索引和执行计划；最后通过 JDBC 连接 Java 与 PostgreSQL，用 Flyway 管理表结构版本。

重点解决：扣减库存与创建订单是否必须一起成功？两个用户同时更新一项数据会发生什么？索引为什么加速某些查询，却增加写入成本？

**应能做到：** 为用户、知识条目与任务设计表；写联表与分页查询；解释事务边界；用查询计划判断索引效果。

参考：[PostgreSQL 官方教程](https://www.postgresql.org/docs/current/tutorial.html)、[SQLBolt 交互练习](https://sqlbolt.com/)。

## 第四层：可联调的 Java 业务后端

引入 Spring Boot，学习请求路由、请求/响应对象、输入校验、统一异常处理、数据库访问与配置。用已理解的输入与业务职责解释框架机制，而不是只记注解。

实现登录、工作空间、知识条目和任务管理，再加入资源权限、事务、分页与接口测试。认证回答“你是谁”，授权回答“你能操作哪条数据”；知道条目 ID 不能获得访问权限。

**应能做到：** 用 React/Vue 联调；隔离用户数据；非法请求返回明确错误；数据库变更可复现。

参考：[Spring 入门指南](https://spring.io/guides)、[Spring Boot](https://docs.spring.io/spring-boot/reference/)、[MyBatis](https://mybatis.org/mybatis-3/)。

## 第五层：Python 与 AI 服务

学习 Python 类型、函数、模块、异常、类型标注、环境管理和 pytest，再引入 FastAPI、Pydantic 与 httpx。比较两门语言的相同职责和不同表达，避免同时从零维护两套完整业务系统。

Python 服务负责文档处理与 AI 请求。学习异步 I/O、超时、取消与服务间身份验证；async 不意味着所有代码都并发，也不意味着计算都变快。

**应能做到：** 写有输入模型、错误处理和测试的服务，理解阻塞点，完成 Java 与 Python 的调用。

参考：[Python 官方教程](https://docs.python.org/zh-cn/3/tutorial/)、[FastAPI](https://fastapi.tiangolo.com/zh/tutorial/)、[uv](https://docs.astral.sh/uv/)。

## 第六层：大模型应用基础

依次理解 token、上下文窗口、提示词、采样、结构化输出、流式响应、工具调用和嵌入。先直接使用一个供应商的 SDK，看清原始请求与响应，再判断是否需要编排框架。

实现摘要、字段提取与流式问答。输入与输出都要校验；模型返回文本不等于业务执行成功。加入超时、成本统计、有限重试与固定测试集，比较提示修改前后的结果。

**应能做到：** 输出符合结构；前端能流式展示并取消；解释失败、成本与能力限制；密钥仅放服务端。

参考：[OpenAI API 文档](https://platform.openai.com/docs/)、[Hugging Face 学习资源](https://huggingface.co/learn)。具体功能以所选模型与当前 SDK 的支持范围为准。

## 第七层：RAG 与效果评估

基本链路：处理文档 → 切块 → 嵌入 → 检索 → 将证据提供给模型 → 回答并附引用。先用 PostgreSQL + pgvector，减少基础设施数量。

学习分块、元数据、关键词与向量检索、重排、无答案处理和权限过滤。检索到文本不代表用户有权阅读它，身份与工作空间范围应来自可信上下文。

建立固定问题集，分别评估“是否找到正确证据”和“回答是否受证据支持”。回答流畅不能证明知识库可靠。

**应能做到：** 提供可追溯引用；权限隔离；更新文档后可重建；用具体问题和指标比较方案。

参考：[pgvector](https://github.com/pgvector/pgvector)、[Sentence Transformers](https://sbert.net/)。

## 第八层：工具执行、部署与求职项目

先接只读工具，再接需要确认的写操作。学习参数校验、允许范围、幂等、审计、持久任务、重试与恢复；文档或模型生成的内容不能代替用户授权。

用 Docker、反向代理、CI、日志与健康检查部署。理解服务、数据库和后台任务各自的生命周期，以及超时、重启与依赖故障的影响。

**应能做到：** 从干净环境部署；定位失败；演示完整业务流程；解释关键取舍、测试结果与限制。

参考：[Docker 入门](https://docs.docker.com/get-started/)、[GitHub Actions](https://docs.github.com/zh/actions)。

## 用一个项目串起这些能力

主线项目是“团队知识与任务助手”，按层次演进：

| 版本 | 核心能力 | 用来验证什么 |
|---|---|---|
| 命令行版 | 任务增删改查、文件保存 | 编程、状态与测试 |
| 业务 Web 版 | 登录、工作空间、知识与任务 | 数据模型、事务与权限 |
| AI 版 | 摘要、提取与流式问答 | 模型调用与联调 |
| 知识库版 | 文档检索、引用与评估 | RAG、权限与效果 |
| 工程版 | 工具、后台任务、部署与监控 | 可控执行与可靠性 |

就业准备关注能否独立交付、解释和修改这些能力。项目应体现新增的后端与 AI 实践，学习项目不应写成多年后端生产经验。
